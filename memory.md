# SmartCampus AI — Project Memory

## Project Identity
**Name:** SmartCampus AI

**Tagline:** Smarter Complaints. Faster Resolution. Better Campus.

**Purpose:** AI-powered campus complaint management platform.

## Core Problem
College complaint processes can be fragmented, manually routed, difficult to track, and slow to resolve. SmartCampus AI creates a centralized workflow with AI-assisted classification, prioritization, routing, tracking, and analytics.

## Core Workflow
Student submits complaint
→ AI analyzes
→ Category and urgency identified
→ Department recommended
→ Complaint assigned
→ Staff investigates
→ Status updated
→ Resolution submitted
→ Student notified
→ Feedback collected
→ Complaint closed

## User Roles
1. Student
2. Staff / Department Officer
3. Administrator

## AI Capabilities
- Classification
- Urgency detection
- Smart routing
- Duplicate detection
- Summarization
- Sentiment analysis
- Suggested responses
- AI confidence

## Main Complaint Categories
Academic, Hostel, Maintenance, IT/Internet, Transport, Library, Security, Cafeteria, Electrical, Plumbing, Cleanliness, Administration, Other.

## Status Lifecycle
Pending → Under Review → Assigned → In Progress → Resolution Submitted → Resolved → Closed.

## Product Personality
Professional, modern, intelligent, transparent, trustworthy, efficient, student-friendly.

## Visual Direction
Premium enterprise SaaS UI with a clean light theme, navy typography, blue/purple AI accents, rounded cards, subtle shadows, clear data visualization, responsive layouts, and restrained animation.

## Important Product Principles
- AI assists people; it does not replace authorized human decisions.
- Students should always be able to understand complaint status.
- Staff should have enough context to resolve issues efficiently.
- Administrators need measurable operational visibility.
- Demo data must remain fictional.
- Security and privacy must be considered from the beginning.
- The interface should feel like a real deployable product.

## Recommended Technology
Frontend: React + TypeScript + Tailwind CSS.
Backend: Python + FastAPI.
Database: PostgreSQL.
AI: LLM API with an abstraction layer.
Authentication: Secure role-based authentication.
Deployment: Independently deployable frontend/backend with managed database.

## Current Priority
Build a polished end-to-end prototype first, then connect real backend services and AI capabilities.

## Definition of Done
A user can experience the complete complaint lifecycle from submission through AI analysis, routing, staff resolution, notification, and feedback using a consistent professional interface.
